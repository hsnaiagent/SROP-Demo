The four SROP agents

Each agent reads data, applies fixed rules, and writes a result back to the cycle record. The planner (Y) reviews and approves at every gate — agents prepare work; they do not decide alone.

Planner chat → Orchestrator → Submissions → Validation → Intake → LP model · Draft review upload → File-Recognition

1. Orchestrator

The coordinator — runs for the whole cycle.

When it runs
Planner sends chat on Requests; a request is sent; an SLA timer fires.
What it does
Turns free text into per-recipient request drafts; compares against last cycle so nothing routine is dropped; sends reminders and escalations; writes audit entries.
Key rule
Never sends without planner review. If the ask is ambiguous, it asks — it does not guess.

2. Validation Agent

One instance per submission — all run in parallel.

When it runs
A file arrives, is replaced, or a corrected value changes underlying data.
What it does
Checks submissions against history, refinery limits, and cross-source rules. Raises flags with evidence and plain-English explanations.
Key rule
Rules are deterministic code — same input, same flags every time. A crash never looks like “clean.”

3. Intake Agent

The consolidator — builds the workbook the LP model reads.

When it runs
Planner closes the last open flag, accepted data changes, or planner clicks Rebuild.
What it does
Merges six validated sources into one master workbook. Every cell is traceable back to a submission and version.
Key rule
Only clean, justified, corrected, or explicitly assumed data enters. Unresolved values stay out.

4. File-Recognition Agent

The gatekeeper on stakeholder self-service during draft review.

When it runs
A stakeholder uploads a changed file while reviewing the draft SROP.
What it does
Identifies the file shape, diffs against the issued draft, checks authority per cell, and flags extreme values — then shows the verdict to the stakeholder first.
Key rule
Out-of-scope edits become suggestions for the planner — never auto-applied, never silently dropped.
Division of labour: arithmetic, rules, and gates run in code (reproducible). Email wording, chat, and explanations may use an LLM with a template fallback (clearer prose only).
